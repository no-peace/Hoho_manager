# Security Policy

## Supported Versions

Security fixes are applied to the latest version on the `main` branch. Older deployments may not receive security updates.

## Reporting a Vulnerability

Please do not disclose suspected vulnerabilities in public issues, discussions, or pull requests.

Use GitHub's **Report a vulnerability** option in the repository Security tab when private vulnerability reporting is available. Include:
- A clear description of the issue and its potential impact.
- Steps to reproduce the issue or a proof of concept.
- Affected routes, components, versions, or configurations.
- Any suggested mitigation.

If private vulnerability reporting is unavailable, contact the repository owner privately through their GitHub profile and request a secure reporting channel.

## Response

Reports will be reviewed as soon as practical. Please allow time for investigation, a fix, and a coordinated release before sharing details publicly.

## Secret Handling

Never include live Discord tokens, API keys, encryption keys, database credentials, session cookies, or production environment files in reports or commits. Revoke and rotate any credential that may have been exposed.
